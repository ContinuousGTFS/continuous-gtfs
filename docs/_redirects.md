# Redirect map: platform docs site → SDK docs site

The pipeline-authoring pages on the platform docs site (`https://docs.continuousgtfs.com/`) move to this site. A published URL is a promise: every moved page keeps its old URL working through a redirect that ships in the same change that removes the page from the platform site.

This file is the map for that cutover. It is excluded from the rendered site (`exclude_docs` in `mkdocs.yml`).

- **SDK site base, before a custom domain:** `https://continuousgtfs.github.io/continuous-gtfs/`
- **SDK site base, proposed custom domain:** `https://sdk.continuousgtfs.com/`

The paths below are relative to those bases. The SDK site keeps the platform site's paths for every moved page, so each redirect is the same path on the new host.

Inventory taken from `https://docs.continuousgtfs.com/sitemap.xml` on 2026-10-29.

## What the platform site adopts at cutover

The platform site already runs the `mkdocs-redirects` plugin. At cutover it deletes the moved pages and their generators, and replaces its `redirect_maps` with the map below. Targets are absolute, so the plugin writes a redirect page at each old path pointing off-site. The two existing in-site entries (`guide/builtins/schedule.md`, `guide/builtins/realtime.md`) are rewritten to point at the SDK site directly, because their in-site targets are among the deleted pages.

```yaml
plugins:
  - redirects:
      redirect_maps:
        guide/index.md: https://sdk.continuousgtfs.com/guide/
        guide/concepts.md: https://sdk.continuousgtfs.com/guide/concepts/
        guide/writing-transforms.md: https://sdk.continuousgtfs.com/guide/writing-transforms/
        guide/testing-transforms.md: https://sdk.continuousgtfs.com/guide/testing-transforms/
        guide/builtins.md: https://sdk.continuousgtfs.com/guide/builtins/
        guide/pipeline-structure.md: https://sdk.continuousgtfs.com/guide/pipeline-structure/
        guide/id-mappings.md: https://sdk.continuousgtfs.com/guide/id-mappings/
        guide/cli.md: https://sdk.continuousgtfs.com/guide/cli/
        guide/builtins/schedule.md: https://sdk.continuousgtfs.com/reference/builtins-schedule/
        guide/builtins/realtime.md: https://sdk.continuousgtfs.com/reference/builtins-realtime/
        reference/step.md: https://sdk.continuousgtfs.com/reference/step/
        reference/context.md: https://sdk.continuousgtfs.com/reference/context/
        reference/results.md: https://sdk.continuousgtfs.com/reference/results/
        reference/parsers.md: https://sdk.continuousgtfs.com/reference/parsers/
        reference/testing.md: https://sdk.continuousgtfs.com/reference/testing/
        reference/builtins-schedule.md: https://sdk.continuousgtfs.com/reference/builtins-schedule/
        reference/builtins-realtime.md: https://sdk.continuousgtfs.com/reference/builtins-realtime/
        reference/cli.md: https://sdk.continuousgtfs.com/reference/cli/
```

If the custom domain is not live at cutover, substitute `https://continuousgtfs.github.io/continuous-gtfs/` for `https://sdk.continuousgtfs.com/` in every target, and update the targets again when the domain goes live (GitHub Pages then redirects the `github.io` URLs to the custom domain on its own).

The same cutover change on the platform site also:

1. deletes `docs/guide/` and `docs/reference/`, and the Guide and Reference entries in `nav:`;
2. removes `docs/_hooks/builtins.py`, `docs/_hooks/cli_reference.py` and the `mkdocstrings` plugin block (the jobs hook stays);
3. points the platform home page's Guide and Reference links at the SDK site;
4. keeps the generated jobs catalog and its hook as they are.

The plugin does not check whether a source page still exists: it writes the redirect over whatever was rendered at that path. Deleting the pages (step 1) and adding the map in one change keeps the source tree and the published site in agreement.
